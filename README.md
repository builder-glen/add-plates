# gym-points

헬스장에서 **지난번 기록을 보면서** 오늘 운동을 기록하는 모바일 웹앱.

**→ [gym-points.immortal-employee-2021.workers.dev](https://gym-points.immortal-employee-2021.workers.dev)**

---

## 왜 만들었나

운동 기록을 메모장·엑셀·기억에 흩어 관리하면, 바 앞에 서서 "지난주에 벤치 몇 kg 들었지"를 떠올리지 못한다. 그러면 매번 같은 무게에 머물거나 감으로 올렸다가 실패 세트를 만든다.

기록 앱은 이미 많다. 이 앱이 다른 점은 **세 가지 제약을 먼저 정하고 그 안에서만 설계**했다는 것이다.

> **세트 사이 60초 안에, 장갑 낀 손으로, 한 손으로 쓴다.**

그래서 종목을 고르는 순간 지난 기록이 이미 화면에 있고, `ㅂㅊㅍ` 세 글자로 벤치프레스가 잡히며, 세트 입력창이 지난번 무게로 열린다. 앱을 열고 한 세트를 남기기까지 **탭 4회**다.

## 무엇이 있나

| | |
|---|---|
| 기록 | 세트 단위(무게 × 횟수), 하루 여러 세션, 직전 기록 자동 표시 |
| 종목 | 204개. 초성·이름·별칭 검색, 부위 → 세부 부위 → 기구 3단 필터 |
| 일정 | 운동 계획 등록, 구글 캘린더로 내보내기 |
| 내 정보 | 체중·골격근량·체지방률 이력, 추이 그래프, BMI |
| 그 외 | PWA 설치, 다크 모드, 오프라인 대비 저장 |

## 어떻게 만들었나

```
브라우저  ──►  Supabase (Postgres + Auth + RLS)
   │
   └─ Cloudflare Workers 가 정적 파일만 서빙
```

**Vite · React · TypeScript** 정적 SPA / **Supabase** / **Cloudflare Workers**. 운영비 월 $0.

### 서버를 만들지 않았다

중간 서버가 할 일은 "이 요청자가 이 데이터의 주인인가"를 확인하고 DB에 전달하는 것뿐인데, 그 확인은 이미 Postgres의 RLS(행 수준 보안)가 한다. 서버를 두면 같은 판단을 두 곳에서 하게 되고, 코드에서 `where user_id = ...`를 빠뜨리는 실수가 곧 사고가 된다.

RLS로 내리면 그 실수가 무의미해진다 — DB가 어차피 거른다. 그래서 **권한 판단을 코드가 아니라 데이터 옆에 뒀다.**

### 초성 검색은 서버를 거치지 않는다

종목이 204개라 앱 시작 시 전부 메모리에 올린다. 초성(`ㅂㅊㅍㄹㅅ`)은 시드 생성 시점에 계산해 컬럼으로 저장해두고, 검색은 클라이언트가 한다. 검색 API·인덱스·디바운스가 전부 필요 없어지고 타이핑에 즉시 반응한다.

### 칼로리 표시는 넣지 않았다

넣으려다 조사 후 뺐다. 저항운동 에너지 소비는 **합의된 표준이 없고**(2024년 스코핑 리뷰), 효율 상수 공표값이 4%에서 43%까지 갈린다. 무엇보다 계산을 지배하는 변수(템포, 실패 여부)를 이 앱은 기록하지 않는다.

`오늘 320kcal`은 사용자가 체중계 숫자처럼 믿는데 실제로는 계산 방식만 바꿔도 몇 배가 흔들린다. 대신 **총 볼륨**(무게 × 횟수 합계)을 쓴다 — 가정이 하나도 안 들어가고 정확하다.

조사 원문은 저장소에 없다(로컬 문서). 결론만 위와 같다.

### 세부 부위는 근거가 확인된 것만 넣었다

`윗가슴`은 대흉근 쇄골부라는 해부학적 근거와 종단 연구가 있지만, `아랫가슴`·`이두 장두/단두`·`삼두 외측두`·`상하복부`는 통제된 연구에서 차이가 확인되지 않거나 오히려 반증된다. 헬스장에서 통용된다고 해서 앱이 사실처럼 표시하면 안 된다고 봤다.

## 로컬에서 실행

```bash
npm install
cp .env.example .env   # Supabase URL 과 anon key 를 채운다
npm run dev            # http://localhost:5273
```

DB는 `supabase/migrations/`의 SQL을 순서대로 실행하면 만들어진다 — 스키마 → RLS 정책 → 종목 204개 시드.

## 구조

```
src/
  data/        Supabase 쿼리, 낙관적 업데이트, 검색
  features/    home · picker · plan · settings · login
  lib/         날짜·초성·드래그·환경설정
  styles/      토큰(라이트/다크) + 화면별 CSS
supabase/migrations/   스키마 · RLS · 시드
seeds/         종목 마스터 생성 스크립트
scripts/       아이콘·일러스트 에셋 빌드
```
