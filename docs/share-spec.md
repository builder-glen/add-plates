# 오늘 운동 내역 공유

> 2026-09-07 · 스펙 (구현 전) · 디자인 대기

## 무엇을

오늘 한 운동을 **그 시점 그대로 굳혀서** 링크 하나로 남에게 보여준다.
받은 사람은 앱을 깔거나 로그인하지 않고 링크만 열면 된다.

## 정해진 것

| | | 왜 |
|---|---|---|
| 스냅샷 | **공유 시점의 복사본** | 나중에 세트를 고치거나 지워도 남이 본 화면은 그대로다 |
| 접근 | **링크를 아는 사람 누구나** | 기록 하나 보자고 가입하라는 건 공유가 아니다 |
| 내용 | 종목 · 세트 · 총 볼륨 | 메모와 신체 정보는 넣지 않는다 |
| 링크 수 | 한 날짜에 **유효한 링크 하나** | 새로 만들면 이전 링크는 자동으로 죽는다 |

---

## 1. 공유한다

| 사용자 | 시스템 |
|---|---|
| 오늘 기록을 마친다 | — |
| 홈에서 `공유` 를 누른다 | 그날 기록을 복사해 링크를 만든다 |
| | 공유 시트가 열린다 (카톡·메시지 등) |
| 카톡으로 보낸다 | 상대에게 링크가 간다 |

**이럴 땐 이렇게**
- 세트가 하나도 없는 날이면 → `공유` 가 눌리지 않는다. 보여줄 게 없다
- 이미 그날을 공유한 적이 있으면 → **이전 링크는 죽고 새 링크가 만들어진다.** 그렇게 된다는 것을 누르기 전에 알린다
- 공유 시트를 지원하지 않는 브라우저면 → 링크를 클립보드에 복사하고 `링크를 복사했어요` 를 띄운다
- 통신이 끊겨 있으면 → 링크를 만들 수 없다. `잠시 후 다시 시도해 주세요`

**되면 성공**
- 카톡으로 받은 링크를 **로그인하지 않은 기기**에서 열면 기록이 보인다
- 공유 후 세트를 지워도 공유 페이지는 그대로다

---

## 2. 공유받은 사람이 본다

| 사용자 | 시스템 |
|---|---|
| 받은 링크를 연다 | 그날의 기록이 보인다 — 날짜, 종목, 세트, 총 볼륨 |
| | 로그인을 요구하지 않는다 |
| 하단 링크를 누른다 | gym-points 소개(로그인 화면)로 간다 |

**이럴 땐 이렇게**
- 만든 사람이 공유를 취소했으면 → `공유가 끝난 기록이에요` 만 보인다. 무엇이 있었는지는 알려주지 않는다
- 주소를 잘못 쳤거나 없는 링크면 → 위와 **같은 화면**을 보여준다. 있었는지 없었는지를 구분해 알려주지 않는다
- 앱의 다른 화면으로는 갈 수 없다 — 이 페이지만 열린다

**되면 성공**
- 로그아웃 상태·시크릿 창·다른 사람 폰에서 열린다
- 링크를 조금 바꿔 넣으면 아무것도 안 나온다

---

## 3. 공유를 거둬들인다

| 사용자 | 시스템 |
|---|---|
| 설정 → `공유한 기록` | 공유한 날짜 목록이 최근 순으로 보인다 |
| 항목의 `링크 복사` | 클립보드에 복사된다 |
| 항목의 `공유 취소` | 확인 후 링크가 죽는다 |
| | 5초간 `실행취소` 가 뜬다 |

**이럴 땐 이렇게**
- 공유한 게 없으면 → `아직 공유한 기록이 없어요`
- 취소한 링크를 누가 열면 → 2번의 "공유가 끝난 기록이에요"
- **이미 퍼진 링크는 되돌릴 수 없다** — 취소는 앞으로의 접근만 막는다. 이 점을 취소 확인창에 한 줄로 알린다

## 데이터

새 테이블 하나. 기존 기록 테이블은 건드리지 않는다.

```
workout_shares
  id            공유 토큰. 주소에 들어가는 값
  user_id       만든 사람
  performed_on  어느 날의 기록인가
  payload       그 시점 기록의 복사본 (jsonb)
  created_at
  revoked_at    취소 시각. 비어 있으면 유효
```

`payload` 에 담는 것 — **조인이 필요 없게 이름까지 복사해 둔다.** 종목을 나중에 지우거나
이름을 바꿔도 공유 페이지가 깨지지 않아야 한다.

```
{
  date: "2026-09-07",
  totalVolume: 4200,
  entries: [
    { name: "벤치프레스", muscle: "가슴", equipment: "바벨",
      sets: [{ weight: 70, reps: 8 }, { weight: 70, reps: 8 }] }
  ]
}
```

한 날짜에 유효한 공유는 하나다 — 새로 만들 때 그 사용자의 같은 날짜 기록을 먼저 취소한다.

## 접근 제어 — 이 기능의 핵심

지금 앱은 **"내 기록은 나만 본다"를 DB가 강제**한다. 공유 페이지는 로그인하지 않은 사람이 봐야
하므로 그 벽에 구멍이 필요한데, **테이블을 열어주는 방식은 쓸 수 없다.**

미인증 사용자에게 `workout_shares` 조회를 허용하면 조건에 `revoked_at is null` 을 걸어도
**목록 전체를 훑을 수 있다.** 남의 운동 기록이 통째로 공개된다.

→ **테이블은 미인증에게 완전히 닫고, 토큰을 인자로 받는 함수 하나만 연다.**

```sql
create function get_shared_workout(token uuid)
returns jsonb
language sql
security definer   -- 정책을 우회해 payload 만 돌려준다
stable
as $$
  select payload from workout_shares
  where id = token and revoked_at is null;
$$;
```

- 미인증에게 주는 권한은 **이 함수 실행 하나뿐**이다. 테이블 select 권한은 주지 않는다
- 토큰을 정확히 알아야만 하나를 꺼낼 수 있다. 목록·검색·열거가 불가능하다
- 만든 사람은 기존과 같은 규칙으로 자기 것만 보고 지운다

**토큰은 UUID v4.** 추측이 불가능하고 이미 스키마 전반에서 쓰고 있다.

## 주소와 화면

```
/s/<토큰>
```

정적 SPA 라 서버 라우팅이 없다. 이미 404 를 `index.html` 로 넘기게 해 뒀으므로,
앱이 뜰 때 주소를 먼저 보고 **인증 검사보다 앞서** 분기한다.

- 이 화면은 로그인 상태를 확인하지 않는다
- 헤더·날짜 스트립·시트가 없는 **읽기 전용 단일 화면**이다
- 앱과 같은 토큰(색·타이포·다크 모드)을 쓴다

## 안 하는 것

| | 왜 |
|---|---|
| **카톡 미리보기 이미지(OG)** | 정적 SPA 라 크롤러가 링크를 열어도 빈 HTML 을 본다. 서버나 별도 함수가 필요해 이번 범위 밖 |
| 이미지로 저장 | 링크로 충분하다. 필요해지면 그때 |
| 만료 기한 | 수동 취소로 충분하다. 기한이 있으면 관리할 것이 하나 더 는다 |
| 공유자 이름 표시 | 구글 계정 이름을 그대로 노출하게 된다. 보낸 사람이 누군지는 카톡이 이미 말해준다 |
| 조회수·누가 봤는지 | 링크만 알면 누구나 보는 구조라 의미 있는 수치가 안 나온다 |
| 댓글·반응 | 이 앱의 범위가 아니다 |

## 구현 순서

```
1. 테이블 + RLS + 함수          → 검증: 미인증으로 목록 조회 시 0건, 함수는 토큰으로만 동작
2. 공유 생성 (홈의 공유 버튼)     → 검증: 링크가 만들어지고 같은 날 재공유 시 이전 것이 죽는다
3. 공유 보기 화면 (/s/<토큰>)    → 검증: 시크릿 창에서 열린다
4. 공유 관리 (설정)              → 검증: 취소 후 링크가 죽고 실행취소로 되살아난다
```

1번이 끝나면 **미인증 상태로 테이블을 직접 조회해 0건인 것을 반드시 확인한다.**
지금 7개 테이블에 대해 확인한 것과 같은 방식이다.
