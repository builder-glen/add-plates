# 오늘 운동 내역 공유

> 2026-09-07 · 스펙 (구현 전) · 디자인 대기

## 무엇을

오늘 한 운동을 **그 시점 그대로 굳혀서** 링크 하나로 남에게 보여준다.
받은 사람은 앱을 깔거나 로그인하지 않고 링크만 열면 된다.

## 정해진 것

| | | 왜 |
|---|---|---|
| 담는 방식 | **링크 안에 기록을 넣는다** | 서버에 아무것도 저장하지 않는다 |
| 스냅샷 | 만든 순간의 값이 링크에 박힌다 | 나중에 세트를 고치거나 지워도 남이 본 화면은 그대로다 |
| 접근 | 링크를 아는 사람 누구나 | 기록 하나 보자고 가입하라는 건 공유가 아니다 |
| 내용 | 종목 · 세트 · 총 볼륨 | 메모와 신체 정보는 넣지 않는다 |

---

## 왜 DB에 저장하지 않는가

처음에는 공유 테이블을 만들고 토큰으로 조회하는 방식을 잡았다. 그러면 이런 것들이 따라온다 —
새 테이블, 미인증 접근을 뚫는 함수, 공유 목록 관리 화면, 그리고 **"남의 기록이 노출되지
않는가"를 계속 지켜야 하는 부담.**

기록을 링크 자체에 넣으면 그 전부가 사라진다. **저장하지 않는 것은 유출될 수 없다.**

대가는 URL 길이다. 실측:

| 하루 기록 | URL 길이 |
|---|---|
| 3종목 × 3세트 | 251자 |
| **5종목 × 4세트** (보통) | **299자** |
| 10종목 × 5세트 | 374자 |
| 15종목 × 5세트 | 387자 |

압축을 거치면 400자를 넘지 않는다. 메신저로 보내는 데 지장이 없고, 어차피 사람이 읽는
주소가 아니다. **취소 기능을 잃는 대신 구조가 3분의 1이 된다** — 그리고 취소는 원래도
반쪽이었다. 이미 상대 폰에 도착한 링크는 어느 방식으로도 못 거둔다.

---

## 1. 공유한다

| 사용자 | 시스템 |
|---|---|
| 오늘 기록을 마친다 | — |
| 홈에서 `공유` 를 누른다 | 그날 기록을 압축해 링크를 만든다 (서버 왕복 없음) |
| | 공유 시트가 열린다 (카톡·메시지 등) |
| 카톡으로 보낸다 | 상대에게 링크가 간다 |

**이럴 땐 이렇게**
- 세트가 하나도 없는 날이면 → `공유` 가 눌리지 않는다. 보여줄 게 없다
- 공유 시트를 지원하지 않는 브라우저면 → 링크를 클립보드에 복사하고 `링크를 복사했어요` 를 띄운다
- 같은 날을 여러 번 공유하면 → 그때그때의 기록이 담긴 **서로 다른 링크**가 만들어진다. 이전 링크도 계속 살아 있다
- 통신과 무관하게 동작한다 — 만드는 데 서버가 필요 없다

**되면 성공**
- 카톡으로 받은 링크를 **로그인하지 않은 기기**에서 열면 기록이 보인다
- 공유 후 세트를 지워도 그 링크가 보여주는 내용은 그대로다
- 비행기 모드에서도 링크가 만들어진다

---

## 2. 공유받은 사람이 본다

| 사용자 | 시스템 |
|---|---|
| 받은 링크를 연다 | 그날의 기록이 보인다 — 날짜, 종목, 세트, 총 볼륨 |
| | 로그인을 요구하지 않는다 |
| 하단 링크를 누른다 | gym-points 소개(로그인 화면)로 간다 |

**이럴 땐 이렇게**
- 링크가 잘렸거나 손상됐으면 → `링크가 올바르지 않아요` 만 보인다
- 앱의 다른 화면으로는 갈 수 없다 — 이 페이지만 열린다
- 인터넷만 되면 열린다. 만든 사람의 계정 상태와 무관하다

**되면 성공**
- 로그아웃 상태·시크릿 창·다른 사람 폰에서 열린다
- 링크 끝을 한 글자 지우면 `링크가 올바르지 않아요`

## 링크에 무엇이 들어가나

```
https://<도메인>/s#<압축된 기록>
```

`#` 뒤에 둔다. **`#` 뒷부분은 서버로 전송되지 않는다** — 호스팅 로그에도 남지 않는다.

담는 값 — **종목명을 그대로 넣는다.** 받는 쪽이 종목 마스터를 몰라도 되고,
나중에 종목을 지우거나 이름을 바꿔도 링크가 깨지지 않는다.

```
{
  d: "2026-09-07",
  e: [
    { n: "벤치프레스", m: "가슴", q: "바벨",
      s: [[70, 8], [70, 8], [65, 6]] }
  ]
}
```

키를 한 글자로 줄인 것은 압축 전 크기를 줄이기 위해서다. 총 볼륨은 담지 않고 **받는 쪽에서 계산**한다 — 값이 하나 더 들어가면 원본과 어긋날 여지가 생긴다.

**인코딩**: `JSON → deflate-raw → base64url`
브라우저의 `CompressionStream('deflate-raw')` 을 쓴다. 지원하지 않는 브라우저에서는
압축 없이 base64 만 한다 — 길어지지만 동작한다.

---

## 주소와 화면

정적 SPA 라 서버 라우팅이 없다. 이미 404 를 `index.html` 로 넘기게 해 뒀으므로,
앱이 뜰 때 주소를 먼저 보고 **인증 검사보다 앞서** 분기한다.

- 이 화면은 로그인 상태를 확인하지 않는다
- 헤더·날짜 스트립·시트가 없는 **읽기 전용 단일 화면**이다
- 앱과 같은 토큰(색·타이포·다크 모드)을 쓴다
- Supabase 에 접속하지 않는다 — 링크만으로 그려진다

## 안 하는 것

| | 왜 |
|---|---|
| **공유 취소** | 링크가 곧 데이터라 회수 대상이 없다. 어차피 상대 폰에 도착한 링크는 어느 방식으로도 못 거둔다 |
| **공유 목록 관리** | 저장하는 것이 없으니 관리할 목록도 없다 |
| **카톡 미리보기 이미지(OG)** | 정적 SPA 라 크롤러가 빈 HTML 을 본다. 게다가 `#` 뒷부분은 서버에 전달조차 되지 않는다 |
| 이미지로 저장 | 링크로 충분하다. 필요해지면 그때 |
| 공유자 이름 표시 | 구글 계정 이름을 그대로 노출하게 된다. 보낸 사람이 누군지는 카톡이 이미 말해준다 |
| 조회수 | 서버를 거치지 않으므로 셀 방법이 없다 |

---

## 구현 순서

```
1. 인코딩·디코딩 (압축 + base64url)   → 검증: 왕복 후 원본과 같고, 실측 길이가 400자 이내
2. 공유 보기 화면 (/s#...)            → 검증: 시크릿 창에서 열린다. Supabase 요청이 0건
3. 홈의 공유 버튼                      → 검증: 비행기 모드에서도 링크가 만들어진다
```

2번에서 **네트워크 탭에 Supabase 요청이 하나도 없는 것**을 확인한다.
하나라도 있으면 로그인 없이 열리지 않는다.
